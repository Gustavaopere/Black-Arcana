## Resource loading and selection

The reload listener discovers `.json` resources under `archetype`. A resource at `data/<namespace>/archetype/human/mage.json` contributes to key `human/mage`: the loader strips the directory prefix and `.json` suffix and does not include the resource namespace in that key. It reads each top-level `profiles` array and appends the parsed entries to that key's list. Per-resource exceptions are logged; the failed resource does not contribute its partially parsed list. Applying a reload replaces the loader's map.

An entry's `id` is optional. After loading, an entry with no ID receives `<key>:<zero-based-index>`; the publisher's six live files have no explicit IDs. For example, their first Human Mage entry is `human/mage:0`. `getProfileById(String,String)` returns the first matching ID or null. Generated IDs depend on list order and datapack contributions; they are not registry `ResourceLocation` identities.

`rollProfile(String,Random)` weights all entries for the requested key. Its biome-aware overload first retains every entry whose `matchesBiome` result is true, then weights that candidate list. Unrestricted entries match any biome and remain eligible alongside restricted matches. If the matching list is empty, it tries entries with a null biome list. Empty candidate lists return null. A weighted draw uses `Random.nextInt(sum(weights))` and the first cumulative weight above the draw; weights and the sum receive no positivity clamp in this code.

`biomes` accepts exact biome IDs and `#namespace:tag` values; matching is an OR across entries. An absent or empty array becomes unrestricted. **All six publisher live files omit `biomes`**, so each live pool is identical across biomes. No special biome spell pools are hidden in the seven texture folders.

`data/acolyte/archetype/exemple.json` is a packaged, comment-bearing schema/example resource. Its derived key is `exemple`; none of the six entity subclasses returns that key. Discovery by the generic loader does not establish a seventh registered entity, a seventh active family, or an additional live spawn pool. Its illustrative fields are documented below as parser support, not added to the 50 live entries or their weights.

## Profile schema and defaults

These are input-field facts, not redistributed JSON or implementation code.

| Input field | Parsed meaning / default |
|---|---|
| `weight`, `tier` | Integers; each defaults to 1. Neither is clamped here. |
| `id` | Nullable string; generated by the loader when absent. |
| `name` | Nullable literal custom entity name. |
| `skin` | Nullable resource location; a value without `:` uses namespace `acolyte`. |
| `biomes` | Optional string array; absent/empty becomes null/unrestricted. |
| `equipment` | Optional object containing `mainhand`, `offhand`, `head`, `chest`, `legs`, `feet`. Missing fields, empty strings, `minecraft:air` and item lookup returning air become null. |
| `stats.xp_reward` | Integer XP reward, default 15. |
| `stats.attack_interval` | Integer goal timing input, default 30 ticks. |
| `stats.barrage_attack_interval` | Integer barrage timing input, default 80 ticks. |
| `stats.barrage_projectile_count` | Integer passed as the barrage count, default 1. It is a host-goal input, not proof of the eventual spell's projectile count. |
| `stats.single_use_spell_delay` | Integer first-single-use delay input, default 30 ticks. |
| `stats.spells_quality` | Float main-mage-goal quality input, default 0.3. It is not a fixed spell level and is not used by warrior/archer barrage calls. |
| Other `stats` keys | Numeric entries retained as a double-valued override map. The shared attribute applicator recognizes only `max_health`, `attack_damage`, `movement_speed`, `follow_range`, `armor`, `attack_knockback`; unsupported keys do not alter attributes there. |
| `spells.barrage_spell`, `spells.single_use_spell` | Optional Iron's spell ID strings; absent fields become null. |
| `spells.attack_spells`, `defense_spells`, `mobility_spells`, `utility_spells` | Optional Iron's spell ID arrays; absence becomes an empty list. Null spell resolutions are omitted from arrays. |

If the `spells` object is absent, the parser also supports those spell fields at the profile's top level. Item IDs resolve through Minecraft's item registry; spell IDs resolve through Iron's `SpellRegistry.getSpell(ResourceLocation)`. No Acolyte spell registry or spell identity is created, and this parser does not independently prove that a referenced host spell can cast in the installed host set.

## Entity application and persistence

Both Human and Demon `finalizeSpawn` methods perform the same main stages: capture six base attribute values; choose a skin variant from 0–2; roll a profile using the entity's archetype key and spawn biome; apply profile stats and XP reward; synchronize custom skin; rebuild goal and target selectors; populate equipment; apply or clear literal custom name; resolve and synchronize the biome texture folder; then call the host spawn finalizer.

`ArchetypeUtils` captures/resets max health, attack damage, movement speed, follow range, armor and attack knockback. Recognized overrides set **base** attribute values. When `max_health` is overridden, application also sets current health to the resulting maximum. The override's armor is consequently a base attribute contribution, not a promise of total armor after worn items or other modifiers.

Human equipment population applies head, chest, legs and feet (a null clears the slot), and applies mainhand only when the current mainhand stack is empty. Demon equipment population substitutes a random item from `acolyte:demon_horns_0` through `_3` when profile head is null; the other behavior is the same. Although `offhand` is parsed, neither shared population method applies it. `ArchetypeUtils.applySlot` sets a non-null item as a new stack and sets that slot's drop chance to 0; its null branch clears the stack.

Both families save `SkinVariant`, `BiomeFolder` and `ArchetypeProfile`; Humans additionally save recruitment/stay/anger state under their respective contracts. On load, a saved profile ID is resolved against the loader's current map, then profile stats and custom skin are applied and goal selectors are rebuilt. These read methods do not reroll a missing profile, call the spawn equipment-population method, or reassign XP reward. Their base-attribute capture call occurs in spawn finalization, not in these read methods. A reload replaces the loader map; it does not traverse existing entities to replace their retained `selectedProfile` objects. Effective behavior after reload/restart remains a runtime verification item.

## Biome texture variants

The mapping reads the **biome path text**, independent of namespace or biome tags. It uses the first matching rule in this order:

| Biome path condition | Folder |
|---|---|
| contains `taiga` | `taiga` |
| contains `desert` | `desert` |
| contains `jungle` | `jungle` |
| contains `savanna` | `savanna` |
| contains `snowy` or `frozen` | `snowy` |
| contains `swamp` | `swamp` |
| contains `badlands` | `desert` |
| other path, or missing biome key | `plains` |

Each folder packages `human0.png`–`human2.png` and `demon0.png`–`demon2.png` at `assets/acolyte/textures/entity/generic_skin/<folder>/`. Custom skin, when present, takes precedence over the generated texture location. Default texture state is plains/variant 0; the family cards record their actual fallback texture constants. These are asset-path facts only; no texture data is copied here.

## Technical boundaries

Profile selection has no attack target, mana/emerald cost, cast duration, effect duration, damage, attack radius, projectile entity or motion of its own: **N/A**. It supplies stats, equipment and host goal inputs. Nominal conversion is 20 game ticks per second; server tick rate determines elapsed wall time. Main mage quality-to-level conversion, spell range/cost/damage/cooldown and cast/projectile resolution are delegated to Iron's. Barrage and single-use calls in these six role subclasses supply level bounds **1–1**. Entity reach, melee/ranged scheduling and target policy belong to the linked role cards; Human hiring cost and duration belong to [recruitment](recruitment-contract.md).
